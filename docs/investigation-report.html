● Verdict — No malware present

There is no trojan.kill.av.exe, and no virus of any kind.

No file by that name — and no trojan, dropper, antivirus-killer, or Windows malware — exists in any working tree, on any branch, or anywhere in the full commit history of the eight repositories examined. trojan-kill-av is only this investigation's branch name.

The investigation did surface one high-severity design/configuration risk: the "Jacky / SAS" project is built to expose the PC's shell and filesystem over an API and an optional public tunnel, and that access is unauthenticated by default. That — not a virus — is what to check on the actual machine.

2 · Why "trojan" and "AV" appear — all benign

  • SOC threat catalog — VeilOps.tsx embeds a MITRE ATT&CK reference dataset (TrickBot, Dridex descriptions). Read-only analyst reference data, not code.
  • Cyber-ethics rulebook — CyberSecurityRulebookApp.tsx's "T — Trojan Payload Distribution" entry describes a technique alongside its legal consequence and ethical alternative. Awareness content.
  • "AV" = Avast, and the code keeps it running — SECRETS.md / cloud_client.py use truststore to make HTTPS work through Avast's interception with TLS verification left ON ("no CERT_NONE … Avast keeps protecting the machine"). Nothing attempts to disable AV.
  • Cosmetic string — a retro fake window titled "Gemini Prompt.exe". Just a UI label.

3 · What the project actually is

An AI-assistant / "PC operator" fleet called Jacky / SAS, built with Lovable and several AI coding agents. jacky is a Python Flask engine running on the owner's Windows PC that can run whitelisted PowerShell; pc is a browser "virtual computer" with a Node backend that runs whitelisted shell commands and a sandboxed filesystem; ocd-jacky-777 is the public web UI plus Supabase functions that relay to the engine. The security weight is entirely in how that remote-control surface is exposed.

5 · Findings, ranked

F1HighRemote PowerShell/shell surface is unauthenticated by default

jacky/jacky_api.py exposes POST /api/shell, running powershell -NonInteractive -Command via subprocess. Auth is opt-in — on only when SAS_ACCESS_TOKEN is set — and the route has an explicit "Open SAS — allow" path, so with no token set it executes commands with no authentication. pc/server.ts has the same shape: /api/shell/exec and /api/term-fs/{read,write,rm}, where requireAuth() returns allow when the token is unset, bound to 0.0.0.0.

Mitigations present: command allowlists; pc uses execFile with an argument array (not a shell string), blocks metacharacters and .., enforces a workspace root with symlink checks, plus a lockdown flag and rate limiter. An approval/transaction framework exists in jacky but is not wired into the live /api/shell route.

F2HighA one-command launcher puts the PC on the public internet

jacky/Start_SAS_Public.ps1 opens a Cloudflare quick tunnel to the local server and prints a public URL for the dashboard and API. With no token set it prints a warning but does not refuse to start. Combined with F1, running it without a token exposes an unauthenticated remote-shell API. No evidence of a currently-live exposure (the intended domain does not resolve and quick-tunnel URLs are ephemeral), but the one-click path exists.

F3MediumCommitted Supabase config (anon key) in a non-ignored .env

ocd-jacky-777/.env holds the Supabase URL and the anon/publishable key (tracked since 2026-04-12, ~548 historical blobs). The anon key is designed to ship to browsers and is only safe with Row-Level Security enforced. The real defect is that .env is not git-ignored in any of the five original repos — so a service-role key committed later would leak silently. Confirm RLS; move secrets to the platform; add .env to .gitignore; rotate if desired.

F4MediumPC internals disclosed in public repos

Public repos document the PC's drive map (E:/G:/V:/H:), hardware ("GODZILLA", RTX 3090, 128 GB RAM), a Windows user path, the intended domain, and the full tunnel setup. No credentials, but useful reconnaissance in aggregate. Consider moving the operational runbooks to a private repo.

F5Low"Secrets" found are placeholders / test fixtures — not real keys

These matched secret patterns but are intentional, listed so they are not mistaken for leaks: the literal AWS docs example key AKIAIOSFODNN7EXAMPLE and a sample sk-proj-… in a scanner-demo app; sk-live-… and a dummy RSA key in Jackie test fixtures; sk-ant-PASTE_YOUR… and Telegram env-var names in templates; and a Firebase web API key (public by design). No real AWS secret, OpenAI/Anthropic key, GitHub token, bot token, or private key was found in any tree or full history.

F6LowModel downloader can fall back to pickled checkpoints

scripts/download_models.py prefers safetensors but will fall back to pickled PyTorch weights — a known code-execution vector for untrusted model repos. Prefer safetensors only, or load with weights_only=True.

F7InfoComment-triggered CI workflow with write permission

jacky's agent-tasks.yml runs on @OmniAgent issue comments with contents: write. It passes the comment body through an environment variable (a safe pattern) and runs on GitHub-hosted runners. Low risk as written; noted for periodic review.

F8InfoThe Supabase relay is the correct pattern — a positive finding

jacky-proxy relays the browser to the engine behind a strict path allowlist, mandatory auth, and an admin gate on the master switch — and deliberately excludes /api/shell from the allowlist, with comments calling it out as dangerous. PARITY_MATRIX.md openly documents the open-by-default behaviour as a known risk. The team is aware; the gap is that the default is open rather than closed.

8 · Recommendations

On the PC itself — where real evidence would live

  1. Review Windows Event Viewer, Avast history, and Defender history from 2026-06-28 onward.
  2. Inspect jacky's runtime artifacts — sas_serve.log, tunnel.log, CURRENT_PUBLIC_URL.txt — to see whether a public tunnel was ever opened, and when.
  3. Check current listeners on :5000/:11434 and Task Scheduler (the project's own JackyAutoSave task is expected and benign).
  4. Confirm whether the access tokens were ever set when the public launcher ran.

In the code — close the open-by-default gap (F1/F2)

  1. Make auth fail-closed: refuse to start shell/filesystem endpoints, and refuse to bind beyond 127.0.0.1, unless a token is explicitly set.
  2. Wire the existing approval/transaction framework into the live /api/shell route.
  3. Default SAS_HOST to 127.0.0.1 in serve.py.

Hygiene (F3–F6)

  1. Add .env to .gitignore; move real secrets to platform stores; confirm Supabase RLS; rotate the key if warranted.
  2. Move operational runbooks (drive maps, hardware, tunnel setup) to a private repo.
  3. Prefer safetensors in the model downloader; avoid the pickled-weight fallback.

9 · Conclusion

The "trojan.kill.av.exe" does not exist in any of these repositories or their history, and no malware, antivirus-killer, or hostile payload was found. "Trojan" is defensive/educational catalog content, and the Avast references show the code is written to keep antivirus running. The genuine risk is architectural: a system designed to expose the owner's PC to remote shell and filesystem control, with authentication off by default and a one-click public-tunnel launcher. There is no evidence of a currently-live exposure, but if that launcher was ever run without a token, a remote-control surface was on the internet during that window. The forensic answer moves from "find the virus" to "check the PC's logs and the server/tunnel runtime artifacts for the 2026-06-28-onward window, and close the open-by-default auth gap."
